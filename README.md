# 몽글몽 · MongleMong

바탕화면에서 고양이형 몽글몬 **카페몽**과 함께 성장하는 시메지 스타일 다마고치 RPG입니다. 여러 모니터의 Windows 작업 표시줄과 창 위를 걷는 동료들을 돌보고, 던전 코어를 배치해 전투·성장·아이템 수집을 즐길 수 있습니다.

**현재 버전은 0.11.0입니다.** 이 저장소에는 **유저용 클라이언트 소스만** 관리합니다. 관리자 제작 도구와 서버 운영 소스는 별도 비공개 작업 공간에서 관리하며, 이 저장소의 빌드·자동 검사·배포 대상에 포함하지 않습니다. 분리 기준과 업로드 절차는 [유저 소스 관리 안내](docs/PUBLIC-WORKFLOW.md)에 있습니다.

## 소스를 받아 실행하기

소스 개발에는 [Node.js 24 LTS](https://nodejs.org)를 권장합니다. 접근 권한이 있는 계정으로 인증하고 **Code → HTTPS**에서 복사한 주소를 아래 자리표시자에 넣습니다.

```powershell
git clone "복사한_HTTPS_주소" MongleMong
cd MongleMong
npm.cmd ci --include=dev
npm.cmd run hooks:install
npm.cmd run preview
```

브라우저 미리보기는 `http://localhost:3000`에서 확인합니다. 데스크톱 소스 실행은 `start-windows.cmd` 또는 `npm.cmd start`를 사용합니다. 기본 계정 서비스 주소는 `https://monglemong.kr`이며, 로그인하지 않으면 기존 게스트 플레이를 계속할 수 있습니다. 설치 완료된 게임을 플레이하는 PC에는 Node.js가 필요하지 않습니다.

0.9.1까지의 이력을 가진 작업 폴더는 수정 파일을 별도로 보관한 뒤 새 폴더에 clone하세요. 기존 브랜치나 태그를 새 이력에 병합하지 않습니다. 새로 clone한 작업 폴더에서는 `git pull --ff-only`로 최신 소스를 받고 기능별 브랜치에서 수정합니다. GitHub Actions는 업로드된 소스 범위·리소스·테스트를 확인하며 EXE 제작이나 자동 배포는 수행하지 않습니다.

### 업데이트와 업로드

- GitHub에는 유저용 런타임·리소스·빌드 도우미·테스트·문서만 올립니다.
- 커밋 전 `npm.cmd run check:public`으로 Git 인덱스에 올릴 내용을 검사합니다. 새 파일은 승인된 유저 파일 목록에도 등록해야 합니다.
- `npm.cmd run hooks:install`은 Git pre-push 검사를 설치합니다. 업로드할 브랜치·태그의 대상부터 모든 조상 커밋을 검사합니다. 중간 커밋의 관리자 파일을 나중에 삭제하거나 과거 브랜치를 병합해도 차단하며, 과거 이력을 건너뛰는 예외는 없습니다.
- 관리자·서버 소스, 비공개 전달 ZIP, 실제 환경변수·DB, 생성된 설치 파일은 이 저장소에 넣지 않습니다. 비공개 작업 공간과 백업은 별도로 보관합니다.

완료한 업데이트는 필요한 검증과 문서 정리 후 커밋·업로드합니다. 수정·작은 개선은 patch, 기능 추가는 minor, 호환성을 깨는 변경은 major 버전으로 관리합니다. 검사 통과 후 `v<version>` 태그를 남기며, 변경 이력은 [CHANGELOG.md](CHANGELOG.md), 작업 기준은 [AGENTS.md](AGENTS.md)에 기록합니다.

**2026-11-26 이력 정리:** 현재 유저용 소스를 새 시작점으로 삼고, 관리자 코드가 포함된 과거 이력으로 이어지는 `v0.8.0`·`v0.9.0`·`v0.9.1` 태그를 제거했습니다. 이력 정리 시점의 버전은 `v0.9.2`입니다. 기존 clone의 수정 파일을 보존하고 새로 받는 방법은 [이력 정리 후 작업 재개](docs/PUBLIC-WORKFLOW.md#이력-정리-후-작업-재개)에 있습니다. 이 조치는 공개 브랜치·태그에서 도달하는 이력을 정리하며, GitHub의 이전 SHA 캐시나 다른 사람이 보관한 복제본까지 삭제하지는 못합니다.

## Windows EXE 만들기

소스와 빌드 도우미를 제공하며 **EXE는 사용자의 Windows PC에서 제작**합니다. 소스를 로컬 폴더에 완전히 압축 해제하고 `package.json`과 함께 있는 `build-windows.cmd`를 실행하세요. [EXE-만드는법.txt](EXE-만드는법.txt)에 상세 순서가 있습니다.

| 작업 | 명령 또는 파일 | 결과 |
| --- | --- | --- |
| 데스크톱 소스 실행 | `start-windows.cmd` 또는 `npm.cmd start` | 유저용 게임 실행 |
| EXE 없이 런타임 소스 준비 | `npm.cmd run prepare:user` | `build-clients/user` |
| Windows 설치 파일 제작 | `build-windows.cmd` 또는 `npm.cmd run dist:win:user` | `release/user/MongleMong-Setup-0.11.0-x64.exe` |
| 설치 파일 검사 | `npm.cmd run verify:win:user` | 포함 소스·리소스·실행 형식 확인 |

`npm.cmd run dist:win`도 유저용 빌드입니다. 이 소스에서 관리자 빌드나 미리보기를 요청하면 오류로 중단합니다. 관리자용 소스는 별도 비공개 전달본에서 관리합니다.

**카페몽 원본 PNG는 `assets/characters/cafemong.png`에 포함되어 있습니다.** 1536 × 2400 원본을 별도로 가져오거나 다시 임포트할 필요가 없습니다. 기본 리소스가 없거나 규격이 다르면 실행·빌드는 중단됩니다.

도우미는 기본 리소스 검사 → 잠금 파일 기준 의존성 설치 → 유저용 소스 준비 → 설치 파일 제작·검증을 실행합니다. 첫 실행에는 인터넷 다운로드가 필요합니다. 만든 Setup 설치 파일을 한 번 설치하면 바탕화면·시작 메뉴 아이콘으로 CMD 창 없이 실행할 수 있습니다. 다른 사람에게는 Setup 설치 파일 하나를 전달하세요. `win-unpacked` 안의 실행 파일만 복사하면 런타임이 빠집니다.

현재 설치 파일은 코드 서명이 설정되지 않은 Windows x64용입니다. 패키지 검사는 실제 Windows 설치·실행 검증을 대신하지 않습니다.

### 온라인 서비스 주소

실행·미리보기·빌드의 기본 계정 서비스 주소는 **`https://monglemong.kr`**입니다. `src/runtime-config.json`의 주소를 읽으며, 다른 개발 서버를 쓰려면 환경변수로 재정의합니다.

```powershell
$env:MONGLEMONG_API_URL = 'http://localhost:8787'
npm.cmd run preview
```

공개 서버에는 HTTPS를 사용합니다. 환경변수가 설정되지 않았을 때는 소스의 기본 주소를 사용하고, 프로그램에서 명시적으로 빈 문자열을 전달하면 온라인 기능을 끌 수 있습니다. Windows PowerShell 버전에 따라 빈 환경변수 설정은 변수를 제거할 수 있으므로, 완전한 게스트 전용 빌드는 `src/runtime-config.json`의 `apiBaseUrl`을 비운 뒤 준비하세요.

주소 반영은 서버 배포 완료를 뜻하지 않습니다. 계정 서버·DB·HTTPS가 실제로 연결되어야 회원가입과 온라인 저장을 사용할 수 있습니다. 연결이 준비되지 않아도 이 기기의 모험은 유지됩니다. 운영 설정과 관리자·서버 소스는 별도 비공개 전달본에서 관리합니다.

### 실행 오류

- Node.js 또는 npm을 찾지 못하면 Node.js 설치 후 터미널을 다시 엽니다.
- 개발용 Electron 실행 파일이 없으면 `npm.cmd run setup:electron`으로 공식 런타임 다운로드를 다시 시도합니다.
- 다운로드나 패키지 검증이 실패하면 표시된 오류를 해결한 뒤 다시 실행합니다. `npm audit fix --force`는 Electron 설치 명령이 아닙니다.
- 계정 화면에 연결이 준비되지 않았다고 나오면 서비스 주소를 지정하고 다시 실행·빌드합니다. 로그인 오류가 계속되면 서비스 운영자에게 확인합니다.
- 오류 공유 시 환경변수 파일이나 인증 토큰을 함께 보내지 마세요.

## 자체 계정과 온라인 저장

**설정 → 계정**에서 몽글몽 아이디·비밀번호로 회원가입하고 로그인합니다. Google 계정과 OAuth 설정은 사용하지 않습니다. 로그인·로그아웃·비밀번호 변경·온라인 저장 확인·계정 삭제를 같은 화면에서 처리합니다.

아이디는 영문 소문자로 시작하는 영문 소문자·숫자·밑줄 4~32자입니다. 비밀번호는 12자 이상, UTF-8 기준 최대 72바이트입니다. 비밀번호를 바꾸거나 계정을 삭제할 때는 현재 비밀번호를 다시 확인합니다. 비밀번호 변경은 다른 기기의 로그인도 해제합니다. 비밀번호 분실 시에는 운영자의 본인 확인과 복구 절차가 필요하며 이메일 자동 재설정은 제공하지 않습니다.

기존 기기 저장과 온라인 진행도는 분리됩니다. 처음 가입한 계정은 서버에서 새 모험을 시작하며, 기기의 저장을 자동으로 서버에 올리지 않습니다. 로그아웃하면 기기의 모험으로 돌아갑니다. 다른 기기에서 같은 아이디로 로그인하면 온라인 저장을 이어받습니다. 기존 Google 계정과의 자동 연결·이전은 하지 않습니다.

비밀번호는 서버에서 해시로 저장합니다. 앱은 비밀번호를 파일이나 웹 저장소에 보관하지 않으며, 데스크톱 로그인 유지에는 운영체제 보안 저장을 사용합니다. 온라인 게임 진행과 조건부 동료 획득은 서비스 서버가 판정합니다. 획득 전의 캐릭터 정보·그림은 내려받지 않습니다. 접속하지 않은 동안 성장하지 않으며, 유저가 같은 공간에서 싸우는 멀티플레이 기능은 없습니다.

## 프로그램 업데이트

**설정 → 업데이트**에서 최신 버전을 확인하고 유저용 Windows 설치 파일을 내려받습니다. 설치 파일은 사용자가 실행하는 방식이며 자동 설치·게임 강제 종료는 하지 않습니다. 설치 프로그램의 기존 사용자 데이터 유지 정책을 사용합니다.

업데이트 확인은 계정 로그인 없이 가능합니다. 공개 HTTPS 호스팅의 버전 정보와 설치 파일만 필요하며 별도의 DB나 상시 실행 서버가 필요하지 않습니다. 현재 배포 주소는 `https://monglemong.kr/updates/latest.json`입니다. 아직 파일이 게시되지 않았다면 확인 실패가 표시되며 게임은 계속 사용할 수 있습니다.

운영자는 Windows에서 유저용 EXE를 만든 뒤 다음 명령으로 업로드할 파일을 준비합니다.

```powershell
npm.cmd run prepare:update -- release/user/MongleMong-Setup-0.11.0-x64.exe
```

검증된 유저용 설치 파일과 버전 정보를 호스팅의 `updates` 폴더에 게시합니다. 설치 파일을 먼저 올리고 `latest.json`을 마지막에 교체하세요. 관리자용 설치 파일은 이 배포 경로에 올리지 않습니다. 소스 변경만으로 배포 파일이 생성되거나 업로드되지는 않습니다.

## 검증 방법

```powershell
npm.cmd ci --include=dev
npm.cmd run check:public
npm.cmd run check:assets
npm.cmd run test:all
npm.cmd run test:service-ui
```

계정 UI 검사는 테스트 전용 통신 모의를 사용하므로 실제 계정이나 별도 서버 없이 실행할 수 있습니다. 브라우저 검사는 설치된 Chromium을 사용하며 별도 위치는 `CHROMIUM_PATH`로 지정합니다. 일반 UI·동료는 `test:ui`, `test:roster`, 이미지 저장은 `test:storage`, 배율·창고·드롭은 `test:scale-loot`, 창 이동 모의 검사는 `test:surfaces-ui`, 여러 동료와 모니터 이동 검사는 `test:multi-ui`로 확인합니다. 다중 모니터 검사는 가상 디스플레이와 데스크톱 통신 모의를 사용합니다. 실제 운영 계정 로그인과 Windows 설치·창 인식·서로 다른 배율의 물리 모니터 조합은 대상 환경에서 별도로 검증해야 합니다.

## 여러 동료 함께 키우기 · 0.10.0

**획득한 동료를 최대 6명까지** 동시에 화면에 데리고 나올 수 있습니다. **모험 가방 → 동료**에서 동료별로 데리고 나오거나 돌려보내세요. 화면에는 최소 한 명이 남아야 합니다. 기본 동료는 카페몽 한 명이며, 이번 기능으로 미획득 동료가 새로 생기지는 않습니다.

각 동료는 따로 이동하고 체력·마나·포만감·행복·경험치·공격 간격을 관리합니다. 동료를 클릭하거나 상세 창에서 선택하면 상태 카드와 돌보기·명령의 대상만 바뀝니다. 다른 동료는 화면에 남아 자신의 명령을 계속 수행합니다. 대기 중인 동료는 자동으로 성장하거나 회복하지 않습니다.

같은 모니터에서 싸우는 동료들은 몬스터 처치 경험치를 함께 얻습니다. 골드·아이템·누적 처치·던전 완료 보상은 파티가 한 번만 받습니다. 다른 모니터에 있거나 휴식 중인 동료는 해당 전투의 경험치를 받지 않습니다.

## 모니터 이동과 Windows 창·작업 표시줄 위에서 걷기

**Windows 데스크톱 앱**에서 화면에 나온 각 동료가 작업 표시줄 위와 열린 창의 위쪽 테두리를 걸을 수 있습니다. **설정 → 일반 → 창 위에서 걷기**는 기본으로 켜져 있으며, 같은 화면에서 감지 상태를 확인하고 끌 수 있습니다.

- 각 캐릭터를 잡아 가로·세로로 끌어 원하는 곳에 놓으세요. 모니터 경계를 넘겨 놓으면 해당 모니터에서 활동합니다. 왼쪽·위쪽 또는 위아래로 배치한 모니터도 지원합니다.
- 같은 모니터 안에서도 원하는 위치로 옮길 수 있습니다. 가까운 창의 위쪽 테두리에 붙거나 아래쪽 창·바닥으로 떨어져 착지합니다. 캐릭터가 들어갈 폭과 머리 위 공간이 있는 테두리에 놓을 수 있습니다.
- 창 위에서는 양 끝에서 방향을 바꾸며 걷습니다. 발판인 창을 이동하거나 크기를 바꾸면 캐릭터도 따라 이동합니다.
- 발판인 창을 닫거나 최소화하면 아래쪽 표면으로 떨어집니다. 다른 창에 가려진 테두리, 최소화된 창, 게임 자체의 창은 발판으로 사용하지 않습니다.
- **모험** 명령을 내리면 바닥으로 내려가 기존 던전의 몬스터와 전투합니다. 던전 입구와 몬스터는 계속 바닥에 배치됩니다.

동료별 모니터와 가로 위치는 저장됩니다. 연결된 모니터 배치가 바뀌면 남아 있는 모니터를 기준으로 위치를 맞추고, 모니터를 분리하면 그곳의 동료를 기본 모니터로 돌려보냅니다. 메뉴는 기본 모니터에서 사용합니다. 브라우저 미리보기는 브라우저 화면 안에서만 이동하며, Windows 창을 감지할 수 없는 환경이나 감지 실패 시에는 해당 화면의 바닥에서 움직입니다.

창 인식에는 Windows에 기본 포함된 PowerShell과 Win32 API를 사용하며, 별도 콘솔 창을 표시하지 않습니다. 창의 위치·크기와 겹침 순서만 읽습니다. 추가 npm 패키지·C++ 빌드 도구·별도 네이티브 EXE 제작은 필요하지 않으며, `electron/native/window-surfaces.ps1`도 기존 빌드에 포함됩니다. PowerShell 실행을 제한하는 PC에서는 창 인식이 작동하지 않을 수 있습니다.

디스플레이 위치는 Electron의 논리 좌표(DIP)로 통일하며, 배율이 다른 모니터의 위치 계산도 자동 검사합니다. 실제 Windows 기기에서의 창 인식·작업 표시줄·물리 모니터 사이 드래그와 다양한 디스플레이 배율 조합은 아직 실행 검증하지 않았습니다.

## 동료 수집과 상세 정보

새 게임의 기본 캐릭터는 **카페몽 한 명**입니다. 온라인 계정은 서버에서 정한 조건을 만족하면 비공개 동료를 획득합니다. 미획득 동료의 정보와 그림은 내려받지 않습니다. 기존에 직접 만든 게스트 동료는 해당 기기의 저장에 남으며 온라인 카탈로그에 자동 등록되지 않습니다. **동료 탭은 획득한 동료를 3열 카드로 표시**하고 세로로 스크롤합니다.

## 캐릭터 크기

바탕화면과 초원에 등장하는 캐릭터는 이전 버전의 **2배 크기**로 시작합니다. **설정 → 일반 → 캐릭터 크기**에서 **1배 / 2배 / 3배**를 선택하면 즉시 적용되고 다음 실행에도 유지됩니다. 1배는 이전 크기이며, 배율 설정이 없던 기존 저장을 열어도 기본 2배를 적용합니다. 모든 동료가 같은 표시 배율을 사용합니다.

배율은 화면에 표시되는 크기만 바꿉니다. 전투 능력치와 이동 속도는 그대로이며, 상태 카드의 초상화·동료 목록 그림 크기는 변경하지 않습니다.

## 던전과 전투

- 새 게임은 120골드와 새싹 숲 코어 2개로 시작합니다.
- 코어는 상점과 오늘의 선물로 얻습니다. 선물은 게스트에서는 기기 날짜, 온라인에서는 서버 날짜 기준 하루 한 번, 새싹 숲 코어 1개와 40골드를 지급합니다.
- 던전은 동시에 3개까지 배치하며, 가까이 겹쳐 놓을 수 없습니다. 정해진 몬스터를 모두 처치하면 입구가 닫히고 추가 골드를 얻습니다.

| 던전 코어 | 출현 몬스터 | 수 | 권장 레벨 | 가격 |
| --- | --- | ---: | ---: | ---: |
| 새싹 숲 | 숲 슬라임 | 3 | 1 | 40 G |
| 버섯 숲 | 꼬마 버섯 | 4 | 3 | 80 G |
| 달빛 동굴 | 수정 정령 | 5 | 5 | 140 G |

- 몬스터 처치로 같은 모니터에서 싸우는 동료들의 경험치와 공용 골드를 얻습니다. 레벨이 오르면 체력과 마나를 모두 회복합니다. 카페몽은 위 표의 성장치를 매 레벨 적용합니다. 다른 동료는 개별 설정된 성장치를 따르며, 모두 최대 레벨은 50입니다.
- 마법 공격은 마나 6을 사용합니다. 마력이 공격보다 높은 동료는 마나가 충분하면 마법으로 공격하며, 다른 동료는 세 번째 공격마다 마법을 사용합니다. 마나가 부족하면 물리 공격을 합니다. 수정 정령의 공격에는 저항력이 적용됩니다.
- 산책 중에도 가까운 몬스터와 싸우며, 모험 명령을 내리면 적극적으로 몬스터를 찾아갑니다. 휴식 중에는 공격받지 않습니다. 체력이 소진되면 자동으로 휴식합니다.
- 휴식은 초당 체력 4와 마나 3을 회복합니다. 시간이 지나면 화면에 나온 각 동료의 포만감과 행복이 감소하고, 포만감이 아주 낮으면 공격 피해가 줄어듭니다.

## 창고와 몬스터 아이템 드롭

몬스터를 처치하면 아래 두 아이템의 획득 여부를 **각각 독립적으로** 판정합니다. 획득한 아이템은 화면에 알림이 나타나고 **모험 가방 → 창고**에 자동 보관되며, 바닥에서 따로 줍지 않아도 됩니다. 던전 코어 수량과 사냥 아이템 수량은 별도로 관리합니다.

| 몬스터 | 일반 재료 · 확률 | 희귀 재료 · 확률 |
| --- | --- | --- |
| 숲 슬라임 | 슬라임 젤리 · 60% | 숲의 씨앗 · 10% |
| 꼬마 버섯 | 버섯 포자 · 60% | 빛나는 버섯 · 10% |
| 수정 정령 | 수정 파편 · 60% | 달빛 결정 · 10% |

각 판정에 성공하면 해당 아이템 **1개**를 획득하므로 한 마리에서 아무것도 나오지 않거나, 한 종류 또는 두 종류가 함께 나올 수 있습니다. 처치한 몬스터는 다시 판정하지 않으며, 재실행해도 같은 처치 보상을 중복 지급하지 않습니다.

창고에는 획득한 아이템의 이름·등급·보유 수량이 표시됩니다. 아이템을 누르면 설명과 획득처·드롭 확률을 확인할 수 있습니다. 같은 아이템은 한 칸에 합쳐지며 종류별 최대 **999,999개**까지 저장합니다. 창고는 동료를 바꿔도 유지되는 공용 보관함이며, 현재 재료는 수집·보관 용도로 사용합니다. 장착·소비·판매 기능은 아직 없습니다.

## 돌보기와 음식 취향

쓰다듬기는 행복과 유대감을 높입니다. 돌보기 탭에서는 아래 다섯 음식 중 하나를 고를 수 있으며 **모든 음식은 10골드**입니다. 선택한 음식의 종류·맛과 현재 동료의 취향 일치 여부를 먹이기 전에 확인할 수 있습니다.

| 음식 | 음식 종류 | 맛 |
| --- | --- | --- |
| 따끈한 고기 꼬치 | 고기 | 감칠맛, 매운맛 |
| 노릇한 생선구이 | 생선 | 짠맛, 감칠맛 |
| 싱그러운 채소 접시 | 채소 | 쓴맛, 감칠맛 |
| 새콤달콤 과일 그릇 | 과일 | 단맛, 신맛 |
| 바삭한 별 쿠키 | 간식 | 단맛, 짠맛 |

기본 음식 효과는 포만감 +25, 체력 +12, 행복 +4입니다. 좋아하는 **음식 종류**가 맞으면 포만감 +10, 행복 +4, 유대감 +1을 더 얻습니다. 좋아하는 **맛 한 가지가 일치할 때마다** 포만감 +3, 행복 +2, 유대감 +1이 추가됩니다. 두 보너스는 함께 적용되며 각 수치는 자신의 최대치를 넘지 않습니다.

대화는 한국어 키워드에 반응하는 로컬 규칙 방식입니다. 성격이나 음식 취향을 물으면 현재 동료의 설정에 맞게 답합니다. 대화 자체에는 LLM이나 외부 API가 필요하지 않습니다.

## 저장과 현재 범위

**게스트 모드:** 기기 내 `localStorage`에 진행 상황을 저장하며, 이전 버전에서 직접 만든 동료의 원본 그림은 같은 프로필의 `IndexedDB`에서 복원합니다. Windows 프로필은 `%APPDATA%\mori-desktop-rpg`입니다. 기존 유저용 앱 ID·저장 키·이미지 DB는 호환성을 위해 유지합니다.

**온라인 모드:** 몽글몽 계정별 게임 진행도와 획득 기록은 서비스 서버에 저장합니다. 서버 캐릭터의 정의·그림도 서버에서 관리하며, 로그인한 계정의 권한과 획득 여부를 확인한 뒤 전달합니다. 서버와 동기화된 값이 기준이며, 게스트 저장 파일은 자동 이전하지 않습니다. 계정 비밀번호는 서버 해시로만 보관합니다.

게스트 초기화는 해당 기기의 진행과 기존 제작 데이터를 삭제합니다. 온라인 초기화는 현재 계정의 서버 진행과 획득 기록을 초기화합니다. 계정 삭제는 해당 서버 계정과 세션·게임 데이터를 삭제하며 공용 캐릭터 카탈로그를 삭제하지 않습니다. 화면에 나온 동료 목록과 선택 대상·모니터·가로 위치를 저장합니다. 실행 중인 창과의 연결은 기기에서만 유지하고 앱 재시작 시 저장된 모니터의 바닥에서 시작합니다. 이전 저장은 기존에 선택한 동료 한 명을 화면에 배치한 상태로 이어집니다.

획득 동료 최대 6명의 동시 활동과 다중 모니터 드래그 이동을 지원합니다. 장비 및 스킬 트리·플레이어 간 멀티플레이는 포함하지 않습니다. 실제 운영 계정 서비스 연결, HTTPS 배포, Windows 설치·투명 창·클릭 통과·디스플레이 배율 조합은 대상 환경에서 별도 검증해야 합니다.

## 파일 구성

- `src/app.js`, `src/styles.css`, `index.html`: 유저 화면·메뉴·드래그·대화
- `src/engine.js`, `src/characters.js`, `src/custom-characters.js`: 게임 규칙과 동료 정의·저장 호환성
- `src/items.js`, `src/warehouse.js`, `src/warehouse.css`: 드롭 아이템과 창고
- `src/account-client.js`, `src/account-ui.js`, `src/account.css`: 계정 인증·동기화·계정 화면
- `src/sprites.js`, `src/sprite-storage.js`: 애니메이션 표시와 기존 로컬 이미지 복원
- `src/desktop-surfaces.js`, `electron/window-surfaces.cjs`, `electron/native/window-surfaces.ps1`: 창·바닥 이동과 Windows 표면 인식
- `src/desktop-layout.js`, `electron/display-layout.cjs`: 다중 모니터 좌표·배치와 기본 모니터 메뉴 위치
- `electron/`: 투명 창·클릭 통과·트레이·단축키·계정 통신
- `assets/characters/cafemong.png`: 카페몽 원본 스프라이트 시트
- `assets/`, `assets/items/`, `build/`: 배경·몬스터·코어·아이템·아이콘
- `start-windows.cmd`, `build-windows.cmd`, `scripts/`: 유저용 소스 실행·빌드·검증 도우미
- `tests/`: 유저 게임·계정 연결·빌드 범위·업로드 정책 검사
- `docs/PUBLIC-WORKFLOW.md`: 유저 소스 업로드와 비공개 작업 분리 안내
- `EXE-만드는법.txt`: Windows에서 직접 EXE를 만드는 순서
