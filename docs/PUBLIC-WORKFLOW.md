# 유저 소스와 비공개 작업 분리

0.9.1부터 이 GitHub 저장소는 **유저용 클라이언트 전용**이며, 0.9.2에서 관리자 코드가 포함된 과거 이력과의 연결도 정리했습니다. 관리자 제작 도구와 서버 운영 소스는 별도 비공개 폴더·로컬 Git 저장소로 관리합니다. 비공개 전달 ZIP도 이 저장소의 파일·Release 첨부·Actions 산출물에 넣지 않습니다.

## 작업 공간

```text
작업 폴더/
  MongleMong/          유저용 GitHub 저장소
  MongleMong-Private/  별도로 보관한 관리자·서버 소스
```

두 폴더를 서로의 하위에 넣지 않습니다. 관리자용 소스에는 자체 실행·빌드·서버 설정 안내가 있습니다. 유저용 소스만 내려받은 상태에서는 관리자 앱이나 서버를 만들 수 없습니다.

비공개 소스는 공개 원격 저장소에 자동 연결하지 않습니다. 필요한 경우 별도 비공개 저장소에 연결하는 작업을 명시적으로 진행해야 합니다. 현재 전달한 비공개 소스와 로컬 Git 이력은 별도로 백업하세요. 이 GitHub 저장소만 복원해서는 새 비공개 변경을 복구할 수 없습니다.

## 유저 소스 업데이트 순서

처음 clone한 작업 공간에는 Git 훅을 설치합니다. Git은 저장소에 포함된 훅을 자동 활성화하지 않으므로 새 clone마다 실행해야 합니다.

```powershell
npm.cmd ci --include=dev
npm.cmd run hooks:install
```

아래 절차는 새 이력으로 clone한 작업 폴더에서 사용합니다. 이력 정리 이전의 clone은 먼저 [작업 재개 절차](#이력-정리-후-작업-재개)를 따르세요. 구현·검사·문서 초안과 로컬 커밋은 먼저 진행하며, 작은 수정마다 버전을 올리지 않습니다. 미출시 변경은 현재 버전을 유지하고 `CHANGELOG.md`의 `미출시 (Unreleased)`에 모읍니다. 변경과 테스트를 마친 뒤 추적할 파일만 명시적으로 스테이징합니다.

```powershell
git pull --ff-only
# 유저용 코드·문서 수정과 필요한 검사 수행
git add <검토한_유저_파일들>
npm.cmd run check:public
npm.cmd run check:assets
npm.cmd run test:all
git diff --cached --check
git diff --cached --stat
git commit -m "변경 내용을 설명하는 메시지"
```

변경이 새 버전으로 묶을 규모가 되거나 중요한 수정이 완료되면 **현재 버전 → 추천 버전, 변경 요약·버전업 이유·검사 결과·호환성 영향**을 사용자에게 제시하고 승인을 받습니다. patch/minor/major는 추천 기준이며 자동 적용하지 않습니다. 승인 전에는 버전 변경·원격 푸시·버전 태그 생성을 하지 않습니다. 문서만 바뀐 경우도 자동 푸시 예외가 아닙니다.

승인 후 패키지·잠금 파일과 README·EXE 안내의 버전을 맞추고, 미출시 이력을 해당 버전으로 정리합니다. 필요한 검사 후 승인된 변경을 커밋하고 `git push`합니다. 같은 업데이트에 대해 이미 받은 승인은 다시 요청하지 않습니다.

`check:public`의 기본 대상은 **Git 인덱스**, 즉 다음 커밋에 들어갈 내용입니다. 작업 폴더에 남아 있는 다른 파일을 검사하려면 아래 명령을 사용합니다. Git 정보가 없는 소스 ZIP도 작업 폴더 검사로 확인합니다.

```powershell
npm.cmd run check:public -- --worktree
```

새 유저 파일을 추가할 때는 `public-source-policy.json`의 승인 목록도 함께 검토·갱신합니다. 관리자·서버·비밀정보·설치 결과물은 승인 목록에 추가하지 않습니다. 검사에 실패하면 잘못 들어온 파일을 스테이징에서 빼고 올바른 비공개 작업 공간으로 옮긴 뒤 다시 검사합니다.

승인된 게임 업데이트를 업로드한 뒤 해당 커밋의 GitHub Actions 통과를 확인하고 `v<version>` 태그를 붙여 올립니다. 기존 버전 태그는 이동하지 않습니다. 문서·작업 지침 정리에는 새 게임 버전이나 태그가 필요하지 않으며 다음 승인된 업로드에 포함할 수 있습니다.

## 업로드 검사 범위

- 승인 목록과 금지 경로·파일 유형으로 유저용 소스만 허용합니다.
- Git 인덱스 검사는 `.gitignore`를 강제로 우회해 추가한 파일도 확인합니다.
- pre-push 훅은 브랜치·태그의 대상에서 도달하는 모든 조상 커밋을 검사합니다. 중간 커밋에 관리자 파일을 넣고 나중에 삭제하거나, 기존의 관리자 코드 이력을 병합해도 차단합니다. 과거 이력을 제외하는 고정 SHA나 예외 구간은 없습니다.
- 태그도 대상 커밋과 모든 조상 커밋을 검사합니다. 유저용 소스 정책에 맞는 이력만 새로 올립니다.
- GitHub Actions는 원격의 파일 범위·기본 리소스·유저 테스트를 재검사합니다. 관리자 빌드, 서버 설치, EXE 제작이나 Release 자동 배포는 실행하지 않습니다.

훅은 로컬 안전장치이며 명시적으로 우회할 수 있으므로 코드 검토를 대신하지 않습니다. 원격 CI 실패는 이미 전송한 내용을 삭제하지 않습니다. 업로드 전에 로컬 검사 결과를 확인하세요.

## 함께 유지하는 공용 코드

게임 규칙이나 공용 계정 연결 코드를 변경하면 비공개 작업 공간에도 필요한 변경을 반영합니다. 전체 폴더 복사나 역방향 병합으로 관리자 코드를 유저 저장소에 가져오지 않습니다. 비공개 소스에 동봉된 동기화·검토 안내에 따라 승인된 공용 파일의 차이를 확인하고, 각 작업 공간에서 필요한 테스트를 실행합니다.

유저 앱의 온라인 연결에는 공개 `MONGLEMONG_API_URL`만 사용합니다. 실제 운영 자격 증명·계정 DB·비공개 캐릭터 원본·백업은 소스 저장소 밖에서 관리합니다. 유저 앱은 자체 아이디·비밀번호 계정 연결과 획득 동료 수신 기능을 사용합니다.

## 2026-11-26 Git 이력 정리

사용자의 명시적인 요청에 따라 현재 유저용 소스를 새 루트 커밋으로 보존하고, `main`을 새 이력으로 바꿨습니다. 관리자 코드가 포함된 과거 계보에 연결되던 `v0.8.0`·`v0.9.0`·`v0.9.1` 태그를 제거하고 `v0.9.2`부터 새 공개 이력을 관리합니다. 0.9.1의 최종 소스는 유저용이었지만 그 부모 이력에 관리자 코드가 있어 기존 태그도 정리했습니다.

게임 동작·기기 저장 호환성·카페몽 원본은 유지합니다. 관리자·서버 작업 공간은 별도의 비공개 0.9.1 소스로 유지하며, 복구용 기존 Git 이력 백업도 공개 저장소 밖에 보관합니다. 이 백업은 공개 원격에 다시 올리지 않습니다.

이번 정리는 브랜치·태그에서 도달할 수 있는 이력을 대상으로 합니다. 이전 SHA를 직접 조회하는 GitHub 캐시나 서버에 남은 Git 객체, 기존 clone·fork·다운로드 사본의 삭제까지 보장하지 않습니다. 이전 SHA가 계속 열리면 GitHub의 [민감정보 삭제 정책](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)을 확인해야 합니다. GitHub 지원은 민감정보 삭제를 지원하며, 민감하지 않은 자료의 삭제는 지원하지 않습니다. 관리자용 소스라는 이유만으로 삭제 지원 대상이 되는 것은 아닙니다.

## 이력 정리 후 작업 재개

기존 폴더에서 일반 pull이나 병합으로 새 이력을 합치지 마세요. 이전 관리자 코드가 다시 연결될 수 있습니다.

1. 기존 작업 폴더의 수정 사항과 필요한 파일을 비공개 위치에 따로 보관합니다. 아직 커밋하지 않은 변경도 포함하며, 확인 전 기존 폴더를 지우지 않습니다.
2. 저장소의 **Code → HTTPS** 주소를 복사하고 새 폴더에 clone합니다.

   ```powershell
   git clone "복사한_HTTPS_주소" MongleMong-clean
   cd MongleMong-clean
   npm.cmd ci --include=dev
   npm.cmd run hooks:install
   ```

3. 보관한 변경 중 유저용으로 필요한 코드만 내용을 검토하여 새 폴더에 수동 반영합니다. 이전 `.git`·브랜치·태그·Git bundle을 가져오거나 이전 이력을 merge하지 않습니다. 관리자·서버 변경은 비공개 작업 공간에서 유지합니다.
4. `npm.cmd run check:public -- --worktree`로 검사한 뒤, 검토한 파일을 스테이징하고 위의 유저 소스 업데이트 순서에 따라 로컬 커밋합니다. 원격 업로드는 승인 후 진행합니다.

기존 clone에서 `git push --all`, `git push --tags`, mirror push 또는 강제 push로 이전 이력을 다시 올리지 않습니다. 이후의 일반 업데이트는 새 clone에서만 진행합니다. 게임 설치의 기기 저장 폴더를 지울 필요는 없습니다.

## 소스와 설치 파일

유저용 소스는 `build-windows.cmd`로 Windows 설치 파일을 만들 수 있습니다. 결과물 이름은 `release/user/MongleMong-Setup-<승인된 버전>-x64.exe` 형식입니다. 자세한 순서는 [EXE 제작 안내](../EXE-만드는법.txt), 게임 기능은 [README](../README.md)를 참고하세요.

관리자용 소스와 설치 파일은 공개 전달 대상에 포함하지 않습니다. 이번 작업은 소스·작업 흐름을 정리하며 EXE를 직접 만들거나 자동 배포하지 않습니다.
